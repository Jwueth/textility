# Quatre procédures ciblées pour l’agent

Ces skills sont des procédures proposées, pas des droits supplémentaires. Ils ne sont pas installés par la présence de ce dossier dans un vault. Aucun n’embarque de script ou de dépendance réseau.

| Skill | Quand l’utiliser | Résultat |
|---|---|---|
| [gd-cadrer-echange](gd-cadrer-echange/SKILL.md) | Le mandat ou l’échange est ambigu | Résultat, responsabilités et limites explicites |
| [gd-curer-document](gd-curer-document/SKILL.md) | Une source ou un brouillon doit devenir exploitable | Proposition sourcée, sans validation implicite |
| [gd-reprendre-contexte](gd-reprendre-contexte/SKILL.md) | Reprendre un sujet ou actualiser un checkpoint | État vérifié dans son périmètre et cache dérivé |
| [gd-reviser-reference](gd-reviser-reference/SKILL.md) | Une référence ou convention doit évoluer | Candidate, impacts, décision et contrôle de l’application |

Lire chaque procédure avant adoption. Suivre [le guide d’adoption](../docs/04-adoption.md) pour Hermes. Les procédures ne dépendent pas des chemins du mini-vault : elles demandent de résoudre les conventions du workspace réel. Aucun nom de modèle, profil, organisation ou plugin n’est imposé.
